### 3.2 shadcn/ui 的使用方式

shadcn/ui 按官方组件源码分发方式使用。基础组件从锁定的官方来源取得，记录组件来源提交、哈希和许可证。官方 CLI、组件导入生成、依赖安装及样式编译全部在 Actions 完成；取得的组件源码提交至新仓库，后续构建不依赖实时下载未固定的 registry。

控制台统一使用 Card、Button、Tabs、Badge、Input、Select、Switch、Slider、Tooltip、Dialog、Sheet、DropdownMenu、ScrollArea 和 Table 等官方组件。数据表组合 TanStack，图表继续使用 ECharts；按需导入，不混入另一套通用控件样式。

定制仅包括宇宙配色、边框、透明度、字体、密度、状态表达和业务内容。保留组件的键盘交互、焦点管理、菜单和弹层行为；不自己实现通用对话框或拖动引擎。

组件树固定为 `react-rnd 容器 → shadcn/ui Card → CardHeader／CardContent／业务数据`。shadcn/ui 的 Resizable 用于分栏布局，本版自由浮动面板统一交给 react-rnd，不将分栏缩放误当作任意位置拖动。

### 3.3 面板拖动、缩放与操作

- 拖 CardHeader 标题区域移动面板；按钮、输入、菜单、表格和内容滚动不触发拖动。
- 支持四边和四角缩放；最小尺寸、最大尺寸及布局参数可视化配置。
- 支持面板置顶、锁定、隐藏、重新显示、最大化和恢复原位。
- 位置、宽高、层级、显示状态与锁定状态按 vault 保存；最大化前保留原布局，恢复后尺寸和位置一致。
- 默认按 SVG 底部六面板排列，窄容器默认分两行；已有用户布局优先，窗口缩小时确保标题和恢复入口可达。
- 拖动、缩放及点击面板不会旋转镜头、移动球体或触发节点选择。
- 球体布局锁与面板布局锁独立，不因锁面板禁止球体操作。
- 不全局修改 Obsidian 文档的选中文字或焦点行为；所有拖动样式只作用于插件容器。
- 缩放面板时图表和虚拟列表响应尺寸变化，隐藏或关闭面板时释放订阅和图表资源。

### 3.4 宿主样式与弹层隔离

主题变量和生成的工具样式限定在插件根容器；Tailwind 全局 preflight 不得重置普通笔记、其他插件或 Obsidian 原生界面。Dialog、Sheet、Select、DropdownMenu、Tooltip 等 portal 挂到当前插件视图的受控弹层容器，保持层级和主题。

不同视图分别管理弹层和 focus，关闭视图后卸载 React、portal、图表和 WebGL 实例。宿主颜色模式变化可以更新插件主题，不改写宿主的主题配置。

## 4. 真三维文件球与宇宙视觉

### 4.1 球体必须具备真实体积

- 每个真实一级目录形成一个大球；名称来自目录树，世界数量不固定为七。
- 每个发光小球对应一个真实文件，包含 Markdown、模板、脚本及纳入范围的其他资产。
- 中心优先绑定真实索引文件；没有索引时使用明确标注的展示锚点，不计入文件统计。
- 文件小球使用真实三维球体网格，分布在完整球面和内部层次，具有透视、前后遮挡和视差。
- 复用 CosmoGraph 材质、微光和标签能力，减弱连线，保持清楚的球形轮廓，避免形成扁平线团。
- 小球轻微悬浮，大球缓慢旋转；幅度、速度、光效和节点大小均可视化调整。
- 中心、分支和内部层次表达文件组织；布局辅助线不冒充真实文件关系。
- 稀疏世界保持真实稀疏，空目录显示空态，不添加虚构文件凑球形。
- 密集世界按显示预算展开，明确标注隐藏数量；搜索和巡查目标可以展开。
- 根目录文件使用“库根文件”展示层，不虚构一级目录。
- WebGL 不可用时显示错误与可操作文件列表，不用 SVG 或平面圆替代三维球。

视觉验收必须同时覆盖三维坐标、真实遮挡、三个方向的旋转和宿主录像，不能只凭截图或 Z 坐标存在宣称完成。

### 4.2 自由宇宙操作

- 大球分散悬浮，每球拥有独立 Three.js Group，共享一套场景、镜头和后处理。
- 选中标题或中心后可移动整球；排版模式提供三轴平移和旋转控件，并支持直接拖动及深度调整。
- 整球移动保持内部相对布局，跨球关系端点同步到两个真实文件小球。
- 世界位置和旋转按稳定 ID 保存，重启和世界改名后恢复。
- 新增世界仅安排自己的位置，不重排已有世界。
- 文件变化、巡查和活动只更新受影响对象及高亮，不重置镜头、选择或全图布局。
- 支持镜头旋转、缩放、定位、搜索、恢复布局及键盘列表浏览。

## 6. 真实蜘蛛、自动扩展、智能体和历史

### 6.1 真实巡查蜘蛛

复用 [Quaternius Spider](https://poly.pizza/m/yRYJiAJyiM) 现成三维模型及动画，登记 CC0 来源和文件哈希。Three.js 加载及播放动画，只定制宇宙材质、轮廓光、大小和任务状态，不自写通用骨骼动画引擎。

- 默认屏幕可辨认尺寸约 96 像素，支持调整，不能缩成难以辨认的光点。
- 每 1.5 秒尝试调度一个文件，变化文件优先，其余轮转；同一内容版本最早 30 秒后复查，均可配置。
- 队列驱动任务、定位、读取、检查和结果；动画不能生成巡查次数或虚假任务。
- 有真实关系路径时沿路径移动，无路径时明确显示“直接定位”。
- 实际读取文件，保存版本、SHA-256、规则、时间、异常和未评估范围。
- 注入语法或链接错误后真实查出，修复后重新读取并更新结果。
- 无任务待命；缓存未就绪、读取失败、模型失配和超限均显示原因。
- 暂停动态只停止视觉运动，暂停巡查停止新检查，历史回放不触发新检查。

默认静态检查 JS／TS 及模块文件、JSON、YAML、Markdown frontmatter、Templater 代码和未解析链接，不执行文件内容。其他文件仍建立索引，未支持的检查范围显示未评估。

业务检查复用现有 v3 schema 的 18 类实体和原引擎，覆盖类型、阶段、目录、属性、项目关系、七天归档资格和发布许可等。文件级结果明确区分“本次实读检查”和“最近全库业务检查”，不得将旧业务结果冒充当前内容结果。

### 6.2 自动发现与“学习”

自动学习是本地发现、登记、同步和提示确认，不调用 AI 自动发明业务规则。

| 变化 | 行为 |
| --- | --- |
| 新一级目录，包括空目录 | 立即建立新球，名称取实际目录，未知职责待确认 |
| 新文件、文件或目录改名 | 更新成员、路径和关系，身份及布局可追踪 |
| 新模板 | 登记来源、版本及明确关联 |
| 新脚本 | 登记语言、版本及静态可证明依赖，不执行 |
| 新插件 | 读取允许观察的清单，展示版本及兼容状态 |
| 兼容 schema 扩展 | 更新实体类型、阶段和展示规则 |
| engine 变化 | 标记变化；经 Actions 验证的新构建才启用新检查逻辑 |

新增目录立即展示，业务引擎未覆盖时显示未评估。扩展信息保存在插件状态目录，不改写业务规范。笔记、模板、代码和 Prompt 中的内容作为被观察数据，不作为执行指令。

### 6.3 智能体活动

提供经过契约校验的本地接收入口，默认关闭，只监听 `127.0.0.1`。按可验证公开接口适配 Codex、Claude Code 和桥接来源；没有接口证据时显示未接入，不读取私人会话文件冒充集成。

支持会话、运行、工具及文件目标，区分成功、失败、取消和未知。文件变化和工具事件分别记录，缺少证据不归因；搜索、部分读取、全文读取和修改分别展示，读取不等于理解。

处理多个会话、重复事件、乱序、缺失、鉴权、限流和来源中断。事件不包含私人正文、自由格式工具输出或凭据。插件不向外部模型、分析平台或存储后台上传 vault 内容。

### 6.4 历史与恢复

默认保留 14 天／100 MiB，提供快照、时间轴和历史回放，保留参数均可配置。回放只展示已有证据，不发起检查或补造动作。

Obsidian 关闭期间发生变化，下次补扫显示净变化和证据缺口，不补造中间过程。截断日志、磁盘拒写、版本升级和容量轮转有明确恢复或降级状态；只处理插件自己的历史文件。

卸载释放监听、计时器、队列、图表、React、WebGL 和端口；重启恢复新插件自身设置、布局和历史。

## 7. 架构和接口

数据流：`Obsidian 文件／元数据事件 → 增量索引 → 模型检查／巡查队列 → 统一观测状态 → 三维图谱与 shadcn/ui 六面板 → 历史记录`。

| 接口 | 内容 |
| --- | --- |
| `WorldDescriptor` | 稳定 ID、一级目录、名称、职责、颜色、中心文件、覆盖状态 |
| `FileDescriptor` | 稳定 ID、路径、类型、内容版本、缓存状态、所属世界 |
| `RelationDescriptor` | 两个真实文件 ID、关系类型、来源和证据 |
| `AssetDescriptor` | 模板／脚本／模型／插件资产来源、版本和显式依赖 |
| `InspectionTask / Result` | 任务、文件版本、哈希、规则、时间、异常和未评估范围 |
| `ObservatoryEvent` | 来源、会话、运行、目标文件、结果和证据等级 |
| `Snapshot` | 当时的世界、文件、关系、异常、模型版本和事件位置 |
| `Settings / LayoutState` | 设置版本、三维位置／旋转、球体锁和面板状态 |
| `PanelLayout` | 面板 ID、位置、宽高、层级、显示、锁定及最大化前布局 |

文件和目录改名保留身份，删除后同路径新建使用新身份。状态按 vault 隔离，保存在新插件目录。渲染适配层统一暴露更新、选中、移动、巡查高亮、暂停和销毁接口；界面与检查相互独立，视觉卡顿不能阻止证据记录。

### 8.2 CI 规则

所有安装、官方组件导入生成、锁文件生成、类型检查、lint、契约、单元、集成、构建、浏览器、真实宿主、性能、截图、录像和打包都在 Actions 运行。本地仅编辑、读取、Git 操作和审阅已下载产物。

依赖精确锁定，工作流 action 固定提交；构建和测试入口有 CI 守卫。官方组件源码与第三方许可可追踪，生成源码不得在每次构建隐式漂移。

流水线：`来源／许可／隐私 → 质量与契约 → 逻辑与组件 → 构建一次 → 浏览器＋真实 Obsidian＋性能 → 总门槛 → 审阅候选`。

下游使用同一份插件构建，候选阶段不重新编译；任一必需任务失败或意外跳过，总门槛失败。

宿主矩阵固定：Windows Obsidian 1.14.4／1.13.7，Linux Obsidian 1.14.4，Windows 另跑实际插件组合。记录宿主 Electron／Node／Chrome。按既有授权重新取得 vault 系统代码、模板和插件进入公开 CI 前逐项审查，仅提交系统代码和合成样本，不提交真实笔记、私人插件配置或未审查的 vault 导出；业务数据采用合成样本，私密正文、会话和凭据不进入产物。
